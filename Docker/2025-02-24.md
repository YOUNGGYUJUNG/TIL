# Docker compose

### version

YAML 파일 포맷 버전을 나타낸다. 도커 컴포즈 버전은 도커 엔진 버전에 의존성이 있으므로 가능하면 최신 버전을 사용하는 것이 좋다. 도커 엔진과 도커 컴포즈의 호환성에 대한 내용은 [도커 문서](https://docs.docker.com/compose/compose-file/)를 참고해 주세요.

아래와 같이 3만 적는 경우 3 버전 최신 버전을 사용한다는 의미이다.

```vbnet
version:'3'
```

### service

생성될 컨터이너를 묶어놓은 단위이다. 여기서는 wordpress와 db 컨테이너를 생성했다.

- wordpress, db는 생성될 서비스의 이름이다. 이 항목 아래에는 컨테이너가 생성될 때 필요한 옵션을 지정할 수 있습니다.

```
services:
  wordpress:
        depends_on:
       - db
    image: wordpress
    ------------ 생략 --------------------
  db:
```

### image

서비스의 컨테이너를 생성할 때 쓰일 이미지의 이름을 설정한다. docker run과 같이 이미지가 존재하지 않는 경우 저장소에서 자동으로 내려받는다.

```
services:
  wordpress:
    image: wordpress
```

### environment

docker run 명령어에서 -e 옵션과 동일하다. 서비스의 컨테이너 내부에서 사용할 환경 변수를 지정한다.

```
 environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_USER: exampleuser
      WORDPRESS_DB_PASSWORD: examplepass
      WORDPRESS_DB_NAME: exampledb
```

### port

docker run 명령어의 -p 옵션과 같으며 서비스의 컨테이너를 개방할 포트를 설정한다.

```makefile
ports:
      - 80:80
```

### volumes

run 명령어에서 -v 옵션과 동일하다.

```groovy
volumes:
      - wordpress:/var/www/html
```

### command

컨테이너가 실행될 때 수행할 명령어를 설정한다. docker run 명령어의 마지막 붙는 커맨드와 같다.

### depends_on

특정 컨테이너에 대한 의존 관계를 나타내며, 이 항목에 명시된 컨테이너가 먼저 생성되고 실행된다.

해당 예제에서는 wordpress는 mysql db에 의존적이기 때문에 아래와 같이 설정한다.

```
wordpress:
     depends_on:
       - db
```

### build

도커파일에서 이미지를 빌드해 서비스의 컨테이너를 생성하도록 설정합니다.

build 항목에 정의된 도커 파일에서 이미지를 빌드하여 서비스의 컨테이너를 생성하도록 한다. image는 빌드되면 생성되는 이미지 이름이다.

```less
services:
  web:
    build: ./composetest
    image: my_web:latest
```

## 느낀점

Dockerfile로 컨테이너 각각 실행하다보니 설정파일도 많이해서 번거로웠는데 Docker compose를 쓰니까 신세계였다. 설정도 이미지를 생성하는 것도 터미널에서도 안하고 파일로 실행만 하면 되니까 너무 편하다.
