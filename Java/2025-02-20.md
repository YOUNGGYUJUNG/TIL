## 내장 로깅 프레임워크

1. Logback (기본값)
- 특징

스프링 부트는 기본적으로 Logback을 사용합니다. XML 혹은 YAML 파일을 통해 로그 설정을 커스터마이징할 수 있다.

대부분의 일반 애플리케이션에서 충분한 성능

- **설정 파일 예시:**

`src/main/resources/logback-spring.xml` 또는 `logback.xml` 파일을 생성하여 설정

1. Log4j2
- 특징

Log4j2를 사용하고 싶다면, Logback 대신 Log4j2 의존성을 추가하고 설정 파일을 작성

멀티스레드 환경이나 높은 부하 상황에서 성능

## SLF4J 인터페이스 사용

- 특징

SLF4J(Simple Logging Facade for Java)는 여러 로깅 구현체(Logback, Log4j2 등)를 추상화하는 인터페이스 제공

## **application.properties/yaml을 통한 설정**

- 특징

로깅 레벨, 패턴 등 간단한 설정은 application.properties파일에서 변경할 수 있습니다.

## **AOP를 활용한 로깅**

AOP(Aspect Oriented Programming)를 사용하여 메소드 실행 전후 로그를 자동으로 남기는 기법도 활용할 수 있습니다

## 느낀점

로그를 남기는 방법과 Logback과 Log4j2를 비교하면서, 로그가 단순한 디버깅 도구가 아니라 시스템 성능과 안정성에 큰 영향을 미친다는 것을 알았다. Log4j2의 비동기 로깅 기능을 도입하면 개발 환경의 효율성을 높일 수 있을 것 같다
