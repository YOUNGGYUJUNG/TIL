# 코레일 with 챗봇

## 5일차

3일차에는 이제 챗봇을 쓰기 위해서는 LLM을 공부해야 해서 LLM이 어떤 기능을 가지고 있는지 어떻게 활용해야 하는지를 공부를 했었다. 그래서 "랭체인으로 실현하는 LLM 아키텍처"이라는 책을 읽었다. 그래서 LLM은 어떤 기능이 있고 어떤 모델을 써야하는지 공부했다.

## 6일차

6일차에는 Nginx의 기능과 jwt의 구성요소를 공부했다. 스프링 시큐리티도 자세히 공부한 적이 없어서 스프링 공식문서를 참고해서 공부를 했다. 공부를 다 마치고 본격적인 코딩을 시작헀다. 먼저 Secuity Config를 설정했다. 맨처음 FilterChain을 설정해야 했다.

기본적인 HTTP Basic설정하고 CSRF 비활성화를 했다. 그리고 JWT를 쓰기 때문에 세션 정책은 STATELESS로 설정해 jwt를 로컬 스토리지에 설치하기로 했다.

그다음 요청별 접근 제어를 해 인증관련 경로는 모두 허용하고 다른 것은 인증하기로 했다. 그다음 JWT 인증 필터를 등록함으로써 설정을 마쳤다.

그다음 JWT 인증필터를 설정해 요청이 들어오면 Bearer 토큰을 추출하고 토큰에서 email을 추출하고 인증 객체를 생성하고 정보를 설정을 했다.

여기까지 하고 4일차는 마무리 했다.

## 7일차

7일차에는 본격적인 코레일 기능을 구현하기 시작했다. 6일차에 구현했던 JWT를 이용하여 회원가입과 로그인을 구현했다. 그다음 열차시간표 조회 
열자 예약을 구현하려고 했는데 이게 생각보다 어려웠다. 특히 열차예약할 때가 까다로웠다.

열차 예약을 할 때 서울 -> 대전 -> 대구 -> 부산 이런 호선이 있고 기차표가 1장 남아있다고 가정을 해보자. 서울->대전, 대전->부산은 예약이
가능하지만 서울-> 부산, 대전-> 대구은 구매가 안되게 막아야 했다. 그래서 이것을 무슨 기준으로 나눠야 하는지 고민을 했다. 지역 기준과 시간 기준으로
나눌 수가 있는데 지역 기준으로 하면 서울 -> 부산을 구매한다고 가정했을 때 가격 계산을 서울 -> 대전, 대전 -> 대구, 대구-> 부산표를 다 사야한다.
이렇게 하면 많이 복잡해질 것 같아 시간 기준으로 계산을 했다.
