- VO( Value Object)

불변성 → final로 선언하잖아 다만 클래스를 final로 선언해도 안에 있는 변수는 final로 선언하지 않음 그래서 이것만으로 설명 불가이다. 얻는 이득→ 데이터가 변하지 않으니까 예측가능하고 신뢰함

동등성 → 두 객체에 같은 값을 넣었는데 객체 = 객체하면 true를 반환해야 할까 false를 반환해야 할까의 답은 내제된 의미가 같다면 같은 객체로 본다 그래서 equals와 hashcode를 자바에선 쓴다

→ 그래서 @Value를 써라  equals와 hashCode 생성, 맴버변수, 클래스를 final로 선언해서 불확실성을 낮춘다.

VO는 식별자(id와 같은)를 가질수 없다.

자가 검증→if-else문이나 try-catch문을 사용하지 않아도 되는 것

요약 : VO로 추구하기보단 불변성, 동등성, 자가검증, 신뢰할 수 있는 객체를 만들어라

- DTO

→ 그저 데이터를 하나하나 일일이 나열해서 전달하는게 불편해서 데이터를 하나로 묶얼서 보내려고 만들어진 객체

DTO의 오해에 대한 사실

1. DTO는 데이터 전송이 필요한 모든 곳에서 사용가능
2. DTO는 getter, setter 없이 내부 데이터를 보낼 수 있다. → public으로 보내면 된다

getter, setter로 보내면 private로 선언한게 무슨 소용이냐? @JsonProperty를 써서 직렬화/역직렬화할 수있다. →이런방식도 있다는 것을 설명하고 싶다 권장이 아니다 getter가 정보은닉에 유리하다.

- Entity

JPA의 @Entity와 DB의 엔티티는 다르다. 엔티티는 크게 3가지로 나눈다

1. 도메인 엔티티

도메인 엔티티는 식별 가능하고 비지니스 로직을 갖고 있으며 조금 특별하게 관리되는 클래스로 만들어진 객체 → 엔티티 개발한다라는 뜻은 도메인 엔티티 개발하겠다는 의미이다.

1. DB 엔티티

정보를 담고있는 데이터를 표현하기 위한 수단

1. JPA 엔티티
- JPA의 엔티티는 관계형 데이터베이스의 엔티티이다.
- @Entity의 객체는 영속성 객체이다
- @Entity의 애너테이션은 영속성 객체를 만들기 위한 도구이다.

결국 영속성 객체를 담는 클래스라고 설명

- ORM

관계형 데이터베이스에 있는 데이터를 객체에 매핑하는 솔루션

자바 진영 솔루션은 JPA와 Hibernate(애너테이션 참조해서 데이터를 가져오는 역할)이다.
